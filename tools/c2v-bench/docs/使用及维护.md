# 使用及维护

## 目录与版本

主测模型应选择实验目录中同步展示的**当前 C2V 默认模型快照**。历史 `intranet-default` 来自旧 `raw.model` 配置，可能与管理员后来设置的 C2V 默认不同，不能仅凭“内网”标签判断。每轮计划冻结实际模型 ID、revision、上下文与输出配置；结构案仍可同时挂载 C2V 和 Anatomy。模型渠道失败或投错入口的任务单独归档，不混入有效比较批次。

本地固定根目录 `03_3d_blockout/seko/c2v/`。远程工程代码位于 `tools/c2v-bench/`；远程媒体/运行记录在该 repo 的 `runtime/c2v-bench/`。两者通过 `--data-root` 对接，不改白模路径。技能本体仍由原 dev 工程管理；本测试台不是新的生成 harness。

```text
bench/                 Python API 客户端、状态记录、独立网页
  web/                 业务案例 / 对照 / 统计 / 历史 showcase
dataset/v0.1.0/         历史冻结 suite / baselines
dataset/v0.1.1/         业务 prompt 更新的冻结版本
dataset/v0.1.2/         当前 suite / baselines / changes / rerun-plan（无密钥）
docs/                  需求、方法、来源、操作说明
tools/                 构建与验证脚本
tests/                 独立 fixtures 回归
source/                原始附件、输入图、参考片（不进 Git）
runtime/               本地 run JSON、原片、验证报告（不进 Git）
```

完成定稿且已用于生成后，案例原文、参考、分类或评价硬指标变化都新建 `dataset/v0.x.y/` 并写变更记录；已正式用于生成的旧套件不可原地改写。新增待补案的实际参数也属于新变体/新版本。结果记录冻结了本次 case、prompt、模型请求与实际回执、skill 请求与回执、suite hash、附件 hash、幂等键、时间事件与人工评审历史。

`tools/build_dataset.py` 是 0.1.0 的构建来源，读取原附件和开发期 discovery。正常使用不要运行它覆盖版本；独立迁移只需固定 JSON 和素材。`tools/inspect_media.py` 获取文档中的四个公开参考片、ffprobe 元信息和关键帧联系表；可选需要 Pillow，只用于素材核对，不影响测试台运行。

`source/business-20261124` 是原样解压结果；重复文件硬链接共享内容，不能原地编辑任何一份以免连带更改。要新增素材应另存新文件。历史 showcase 从已有 `01_video_showcase` 只读，不复制。

## 本地或服务器启动

```bash
python3 bench/server.py --data-root . --dev-url http://10.210.9.14:20211 --port 18942
python3 -m unittest discover -s tests -v
```

服务器部署时 `bench/server.py` 使用远程代码路径，`--data-root` 指向同步后的 runtime 资料目录。只监听 `127.0.0.1`；远程访问通过 SSH 端口转发。不要直接绑定公网或把 Cookie、密码、模型 key 写入 JSON。

```bash
ssh -N -L 18942:127.0.0.1:18942 codevideo
```

日常登录使用现有普通测试账号，不使用管理员。密码只送到固定的 dev 登录接口；Cookie 留在服务内存中，浏览器只持有本地 HttpOnly 会话标识。服务重启后重新登录，同账号可以读取原记录并恢复查询。退出/关闭服务停止该测试台的心跳，dev 仍按自己的配置处理在途任务；不要依赖写死的超时值。

## 恢复与诊断

- 任务 `SUBMITTING` 且回执未知：点击恢复同一计划，复用幂等键；不要另存新计划重复发。
- `CREATING_SESSION`：先在 dev 历史确认是否创建，核对空会话及模型 revision 后手动绑定。无法确认就保留记录，不继续制造会话。
- 上传回执不确定：先查询 dev 附件清单；本工具通过内容 SHA note 恢复已上传回执。没有可靠证据不自动重传。
- 模型配置/Anatomy 包版本变化：使用新批次/新计划，不把新旧 revision 混算。
- 网络/鉴权异常：界面保留错误和状态，不因错误重跑模型。重新登录后刷新或恢复即可。
- 原片较大：完整解码按钮会下载到 `runtime/originals/<model>/<case>/<run>.mp4`，不在每次轮询时下载。超过 4 GiB 的片需另做离线检测。轨迹按需从授权 archive API 下载。

## 清理与交付边界

可以清理可再生成的联系表、临时 `.part` 和结束实验的下载缓存；保留 suite、素材 hash、run JSON、审查结果及必要最终成片位置。不要清理平台 session、冻结技能、原参考素材或别人的任务。不要把采集的模型完整轨迹提交 Git。

代码交付含 bench、固定测试定义、必要 tests、使用文档；业务附件独立存储并以 hash 关联。本轮不创建额外的大压缩包、不复制旧白模压缩包，也不发布新业务服务。

验证命令（`live_*` 不会提交生成任务）：

```bash
python3 tools/validate_dataset.py --media
python3 tools/live_check.py --data-root . --account-file /path/to/test-account.json --prepare-input-session
python3 tools/live_web_check.py --data-root . --account-file /path/to/test-account.json
```

第一项校验定义和本地原始媒体。第二项读取普通账号目录，创建专用空实验会话并上传 Mindflow 三图；结果存 validation，不计模型实验。第三项通过临时本地 HTTP 服务实际验证登录、模型目录、计划、缺输入阻塞、导出与退出；不发 job。凭据路径由运行者提供，内容不打印、不复制到代码。

run 的 `suite_sha256` 使用排序键、保留中文的 JSON 规范化内容 SHA；`validate_dataset.py` 另打印原 JSON 文件字节 SHA。两者用途不同，不应直接混比。任何真正生成前都应冻结当前 dev commit，结果归档用于核验实际技能调用。

切换未来的已冻结套件使用 `--suite-version 0.x.y`，对应 `dataset/v0.x.y/`。旧结果保留自己的输入素材快照与版本；修改过的要求不能合并为同条件分母。


## 批量归档与逐案审核（测试台 0.1.1）

只下载指定正式批次，普通账号需与 run 的 owner 一致；不会调用生成 API，不修改远程 session。以下示例在数据根目录运行，密码通过交互输入；自动化可用 `--credentials-stdin` 从标准输入读取 `{username,password}`，不要放到命令行或提交代码。

```bash
python3 tools/download_originals.py --data-root . --probe \
  --cohort c2v-0.1.0-c2v-default-20261124 \
  --cohort c2v-0.1.0-opus55-sfg-20261124
python3 tools/export_review.py --data-root . \
  --owner 'http://10.210.9.14:20211|trltrltrl' \
  --cohort c2v-0.1.0-c2v-default-20261124 \
  --cohort c2v-0.1.0-opus55-sfg-20261124
```

重复执行下载会校验并复用已完成原片。`.part` 是未完成传输，不展示成原片；下载完成后记录原始大小、SHA-256、job ID、时间和相对路径。完整解码另存 `probe`，不自动填写人工质量结论。文件按 run ID 唯一命名，避免未来同案重复测试覆盖旧结果。

网页需登录才能查看该账号结果；登录后先读本地结果，模型目录在后台加载。成功下载的成片走本地文件 Range 流，可直接拖动播放；缺少本地文件时退回远程接口。服务重启后重新登录，评价历史和原片不丢失。测试台的“下载原片”返回原始 MP4，不是平台压缩预览。

`export_review.py` 将冻结需求、每条结果、路径、校验值、时间与当前人工评价写入 `runtime/review/`，同时在各任务目录生成说明。审核之后重新导出即可更新离线清单。该目录为本地审查材料，不是业务交付包，不与旧 showcase 合并统计。代码版本与测试集版本独立更新。

受限代理链路可以给下载命令加 `--range-bytes 131072 --range-workers 6`：并行下载有明确长度的连续字节段，逐段校验 Range 和大小，再顺序落盘；每条文件最多 6 个请求，内存有界，失败仍保留连续前缀。内容不重编码，适用于小段明显快于长连接的网络。默认仍用普通整文件流，避免在正常网络增加请求数量。独立 CLI 与网页通过文件锁保护 run 记录，下载不会覆盖同时填写的评价。
