# Anatomy 结构拆解适配 gate · 0.1.0

判断的是“这个任务是否适合使用结构拆解 skill”，不是判定模型能完成、视频质量通过或时间达标。Gate 不调用模型，不新增 self-check。

本版先由原文形成有证据的结构化需求，再由统一规则判断；不是靠“原理”“3D”“产品”几个词选技能。规则代码在 `bench/gate.py`，不包含 benchmark case ID、产品名或专用分支。当前人工标注在 `dataset/v0.1.0/gate-intake.json`，网页可以展开核对。后续新 prompt 未完成分类时返回“待确认”，不擅自加载精细建模技能。

## 判定契约

| 条件 | 处理 |
|---|---|
| 目标是具体实体的内部结构或物理机制，内部部件的空间/工作关系是表达重点 | 继续检查 |
| 只需外观广告、文字动效、二维故事、场景运动或跨设备系统流程 | 不适用，使用 C2V 对应技能 |
| 拆解对象不具体、必要输入缺失、分类没有原文依据 | 待确认 |
| 需要工程级 CAD、精密几何或仿真正确性 | 待确认，不把 Anatomy 当工程工具保证 |
| 满足实体/部件条件、输入充分、无需工程级精度，维度要求已明确 | 适用，启用 Anatomy + C2V 视频适配 |
| 明确三维要求 | 保留三维约束；不能用二维 SVG 替代后宣称完整达标 |

输出包括 `status`（suitable / unsuitable / needs_review）、中文理由、适配约束、推荐技能策略与 gate 版本。提交服务重新计算 gate；如果任务未判为 suitable，却配置了 Anatomy，会拒绝计划，避免只改前端选项绕过。

## 本套件结果

| 案例 | 判定 | 原因与适配 |
|---|---|---|
| 08 微波炉原理 | 适用 | 原表格明确“内部结构拆解”，且对象具体；用炉体内部部件和工作关系解释。原文未要求工程精度或写实三维，不能自行加成高精度 CAD 项目 |
| 09 Seko REEL 01 放映机 | 适用，保留三维要求 | 原文点明片门/压片板、输片齿轮/胶片、灯室/聚光镜及三维全貌/特写；Anatomy 的部件组织可用，二维结构图不能替代完整要求 |
| 11 AirTag 定位 | 不适用 | 当前主题是远程定位链路/系统原理，没有要求拆开硬件内部；不因“原理”而触发精细建模 |
| 其它案例 | 不适用当前结构拆解路径 | 重点是发布、品牌、文字、拼贴、卡通、风格或场景演绎；仍可使用 C2V。模板或素材缺失另由输入完整性 gate 阻止提交 |

## 结构案的明确改造

两案原始 prompt 不改写；`prompt_submitted` 在类型和原文之后增加以下制作方式，并在 API 中配置固定 Anatomy 包。网页同时可看原文和实际提交文本：

> 制作方式：使用 Anatomy 组织物体内部结构和工作关系，并结合 C2V 制作完整视频。将交互式拆解或演示状态编排到确定的时间轴，支持按时间定位和离线导出。保留原文的主题、产品、指定文案与维度要求；若原文要求三维展示，不以二维 SVG 替代。

适配器为 `category-prefix+anatomy-video-v1`，其余案例仍为 `category-prefix-v1`。不额外扩充部件数量、镜头数量、时长或造型精度。两组分别统计，不将外挂 skill 的效果与耗时混入普通 C2V 对照。

挂载配置与实际 Skill 调用是两件事；未来运行后需要在原生轨迹核对。当前仅完成 gate、输入和网页基建，尚未提交生成任务，也未声称两案已经达到预期效果。
