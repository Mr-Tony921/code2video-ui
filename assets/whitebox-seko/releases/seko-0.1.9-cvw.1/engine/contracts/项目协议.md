# 项目协议 0.1.0

源输入保留 version=2、work_prompt、segments、duration。每个 seg 需要 id/title/duration/resolved_duration/start/end/prompt；缺省 resolved_duration 采用 duration。嵌在中文前后说明中的 JSON 可以读取。业务镜头按 `分镜N` 或 `【镜头N】` 标记提取，原编号和文本保留；新全局 `shot_001` ID 用于接口稳定引用。支持十进制秒，时间比较容差 0.001 秒；镜头在 [start,end) 生效，全片末尾可采最后状态。

产物 `project.json` 必须有：schema_version、engine_version、source_sha256、revision、duration、segments、shot_plan、scene（Three.js Object3D JSON）、camera_uuid、entities、actors、animation.tracks、authored_camera_cuts、edits、reference_usage、provenance。JSON 内无需密钥、外部网络资源或用户绝对路径。每个实体有稳定业务 id、name、序列化 uuid、parent 和 character；uuid 用于内部连接，不替代业务 ID。

segment 的 shot_ids 引用 shot_plan；原片段时长与镜头归属不可更改。camera cuts 可以细分业务镜头，但不能跨镜。坐标米制、Y 向上、Euler XYZ 弧度、FOV 为垂直角度。轨道用绝对时间，父子对象采用局部坐标。动态持物可用父子组或互斥显隐的持有/放下代理，必须保持身份/结果关系。

`loadProject(project)` 返回 scene、camera、objects（ID→Object3D）、setTime、inspectState、listEntities、dispose。业务宿主自行配置 renderer 并在每帧调用 setTime。检查视角应是独立相机，不能覆盖剧情 camera；原运镜和用户拖动覆盖按绝对时间重建。前端拖动保存 edits，绝不直接改掉基础 tracks 后丢失来源。

编辑操作精确字段：kind、entity_id、start、end，加 `delta`（translate）、`position`（freeze_position）、`rotation`（rotation）或 `visible`（visible）。向量都是父坐标系值。修订保存 parent_sha256 和原 revision，工作区 head 使用比较并交换防止过期覆盖。局部区间边界可能产生位置跳变，必须检查；不得静默扩大范围做全片优化。

业务样例没有提供 shot_plan；内部适配器只根据原输入和其 camera 区间建立侧车索引，`provenance.legacy=true`。新生成不得使用 legacy 豁免。当前只承诺文档中的 helper 子集，其他业务接口需收到实际宿主后适配。
