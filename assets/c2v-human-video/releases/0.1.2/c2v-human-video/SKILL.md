# 真人视频：一体化流程

依次完成 `镜头/声音计划 → 组合素材工具 → 素材核对 → 代码合成 → 集中核对与交付`。生图和图生视频可以组合、复用、多次调用；代码准备与素材等待可重叠。不要拆成两种替代能力，不加载快速模式，不启动创意子代理。

## 共同契约

- 用户原文和指定素材优先；源码 `src/`，最终 `output/final.mp4`。默认 1280×720、24fps、H.264/yuv420p、CRF22/veryfast/faststart。这是常规真人模式，不设5分钟制作目标，也不加载快速模式。素材等待、代码制作、复审和编码单独记录，优先满足真人和业务要求。
- 使用虚构成年真人。产品原图用于关键图参考，也保留在代码产品卡里；不以生成图替代产品真实外形。原品牌、卖点、指定文字用代码绘制，不虚构参数/背书。真人运动与口播不能用照片平移或字幕冒充。
- 私有配置由 `C2V_MEDIA_CONFIG` 或 `~/.config/c2v-media/.secrets` 读取。**不要 Read/cat/打印配置、环境或 key。** 工具自己读取；结构见 [references/provider-config.md](references/provider-config.md)。技能与源码包均不包含模型名称或凭据。
- **效果优先，没有5分钟硬限制，也没有“1图＋1视频”或固定素材数量上限。** 按剧情、动作变化、台词长度和保真需求确定数量，每个素材有明确用途；不要为省调用把讲解挤进一句话，也不要无目标海选。不同剧情需要的新素材不算失败重试。同一素材最多一次针对明确缺陷的替代；替代仍有问题就保留最佳可用版本并说明。API 超时保留原任务 ID，只续查，不换输出路径盲目重提。
- 完成一版后，针对用户要求做一次集中核对：真人实际出镜、产品/品牌、必要文案、关键讲解与声音、准确时长。最多两次局部修正；第二次仅处理新增回归或不同原因的主要缺陷，同一已尝试问题不反复修，不做无目标的美术精修。静态图片效果好不能计为真人动作达标；有音轨也不能计为口播逐字正确。

- 先直接使用随包的 `pipeline.py` 和 `media.py`；工具已配置，不需要探查有哪些视频模型，也不因为没有找到本地真人文件就改画卡通。不能未经用户同意换用不匹配的库存人物、安装 Wav2Lip/TTS/ASR 模型来绕过提供的素材链。工具不可用就保留错误和最后有效产物，明确未满足真人要求。
- 工具自动压缩上传副本为长边≤1280、≤512 KiB JPEG并记录原图/传输哈希，代码产品卡继续用原图。受理不明时停止该素材，不删除 receipt 或改输出名重提。
- 原图字样与 prompt 品牌冲突时保留原图，正文按用户要求，交付说明中披露待确认项；不要擅自给广告画面添加调试脚注，不涂改真实产品字样冒充一致。广告强调真实使用场景、产品与卖点节奏；科普使用观众能懂的图解，不让伪代码代替讲解。

## 阶段 1：一张执行卡

将镜头时间表、真人窗口、代码信息层、每项素材用途、原文字串和音轨入出点写到 `work/media-plan.json`。素材 prompt 同时落盘：图片写人物/场景/构图/留白与产品保持项；视频写动作、镜头和逐字口播。真人口播覆盖开头和关键解释；不要让关键原理只剩静音字幕。句长匹配单段时长，需要时拆成多句、多段，不把整段讲解硬塞进一个短片。同一角色复用关键图与固定外观/服装/声音描述；需要新视角或动作时可以新增关键图。各段保留独立计划与 receipt。

讲解要连贯，避免中途长时间只剩静音图文，合理停顿/片尾除外。可以在代码图解下延续素材中的讲解音轨，不要求全片必须看到人脸。使用原生语音，不在说话脸上覆盖不同文案 TTS 后假称同步。按供应商支持的片段长度分段；本工具已验证6–12秒片段，这不是全片真人时长上限，更长单段需核对接口能力。

整体执行卡与各素材链配置分开保存。首段链 `work/asset-01.json` 示例只表示单项协议，不限制素材总量：
```json
{
  "image_prompt_file": "work/image-prompt.txt",
  "video_prompt_file": "work/video-prompt.txt",
  "references": [],
  "image_out": "assets/generated/hero.png",
  "video_out": "assets/generated/hero.mp4",
  "seconds": 10,
  "resolution": "720p",
  "audio": true
}
```
产品参考图的实际路径填到 `references`。任务明确音频/长度/次数时使用其值。

## 阶段 2：启动一条素材链，同时写代码

```bash
python3 .claude/skills/c2v-human-video/scripts/pipeline.py work/asset-01.json > work/asset-01.log 2>&1 &
echo $! > work/asset-01.pid
```

组合工具先生成图并下载，再以图作 first_frame 生视频。每条链只启动一次，`work/asset-01.json.pipeline.json` 记录阶段/状态。后续不同台词/镜头直接用 `media.py video` 引用已生成关键图，不必每段重生图；新构图再用 `media.py image` 或新链，见 [references/asset-workflow.md](references/asset-workflow.md)。独立素材可在供应商并发允许时小批并行，有依赖的素材等待上游。等待期间写好代码图层和时间线；**不在素材未完成时录制缺真人的全片预览，也不删除素材检查来绕过缺失**。

无需模型反复“看是否好了”：完成代码后，查看一次阶段文件或日志，仍未就绪时使用工具等待同一进程。禁止高频轮询、重复启动、追加模型自审。流水线失败就读取对应 receipt；已受理的任务只能用原 `media.py` 命令续查，不重复生图再启动整链。

## 阶段 3：绑定真实素材并编码

先对到齐素材集中核对：批量规格、带时间标记的联系图，检查人物/产品、动作、关键台词窗口。能听审时核对关键台词与片段衔接；没有听审能力就说明未验证，音量/静音间隔不能证明逐字准确。缺失关键人物、动作或台词时允许针对原因替代素材；细小手部/自然度瑕疵权衡是否影响用户目标。遵守每项一次替代限制，已可用的其它素材不重生。

素材 `downloaded` 才可使用；一次 ffprobe 确认视频尺寸/时长/fps/音轨，再按执行卡绑定素材的入点/出点和全片位置。优先 FFmpeg 拼接与叠加代码图层；Canvas 逐帧合成则先按成片 fps 提取使用窗口，不用浏览器 video.play 或反复 seek。音轨与画面共用同一时间线，真人原声保留，补充画外音仅放在无说话脸的说明片段。

2D/2.5D 图层使用已有 Canvas，真实空间需要时用 Three.js；静态资源预计算、随机数固定、`t` 唯一决定画面。可用附带 `render.mjs`/`capture.mjs`，接口与 c2v-fast 相同；不安装依赖、不重写已有录制器。

## 阶段 4：有限核对并交付

集中看一张覆盖主要镜头与交接点的联系图，核对实际素材、主要文字/产品、叙事顺序、无空白和声音衔接；按需要听审关键口播。按共同契约最多两轮局部修正，同一已尝试问题不重复修；可以按缺口补充素材，不重做无关片段。不要为边缘阴影等细节反复整片编码，修改图层先局部验证，最后合成。自然度、嘴型和逐字口播未验证则注明。最终做完整解码、准确时长、尺寸/fps和所需音轨检查，保留最后可播放成片。

`work/media-summary.json` 记录各素材用途、实际请求/替代次数、受理状态、素材耗时、代码与等待重叠区间、编码/修正次数、实际检查和未解决问题。等待与 API 时间不称为纯推理。追加微调只改用户指定部分，复用其它素材与代码；除非用户要求改真人镜头，不重新生成素材，最多一次局部实现＋一次技术修复，不触发全片重审。
