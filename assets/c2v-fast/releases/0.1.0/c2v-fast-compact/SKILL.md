# 快速模式：紧凑执行卡

遵守用户主题、原文、素材、风格和时长；当前目录 `src/` 是源码，`output/final.mp4` 是交付。短片约 5 分钟为软目标，超时如实记录，不能伪报或删除已生成成片。

一次读完本卡，直接完成下列流程，不再读取其它创意/审美 skill，不启动子代理。

1. **在一次实现中定稿。** 在源码顶端用简短配置记录规格、3–5 个叙事段落、必须保留的文字和素材；同时写完整画面与时间线。不要先开一轮工具调用只写长方案，或在写代码前反复拆解确认。把 `work/plan.json` 的落盘与源码同一批完成。初始化静态资源和几何，随机数固定，画面为时间 `t` 的纯函数。
2. **同等规格，选轻量实现。** 用户指定优先，默认 1280×720、24fps、H.264/yuv420p、CRF22/veryfast/faststart。2D/2.5D 用已有 `@napi-rs/canvas`，确需三维透视用已有 Three.js。保持风格辨识，不添加高面数、复杂景深、阴影/粒子后处理。未要求音频可以无音轨；要求口播则必须可听。用户未授权时不调用外部素材服务，不装现有依赖。
3. **合并确定性工具动作。** 源码导出 `render(ctx,t,{width,height,fps,duration})`，可选 `async init(config)`。已有 Node 包通过 `createRequire(process.cwd()+'/package.json')` 加载。一次执行附带录制器，它会生成 6 格图、一次全片编码、ffprobe 和完整解码检查：
   ```bash
   node .claude/skills/c2v-fast-compact/scripts/render.mjs src/film.mjs --dur <seconds> --out output/final.mp4
   ```
   浏览器方案复用同目录 `capture.mjs`，暴露 `window.seek(t)`、`window.READY=true`，使用 `CHROME_BIN` 和本地 node_modules；随后在同一工具执行中用 ffprobe/ffmpeg 校验。不要让模型来回启动单项检测，不以 `video.play`/墙钟驱动截图。
4. **停止条件明确。** 文件存在、尺寸/fps/时长正确、可完整解码就交付。最多看一次 6 格图；严格单轮时只保留这张图供事后评估，不因看图返工。审美缺陷与未验证点如实说明，不逐帧自审、不重做风格。记录 `work/fast-summary.json` 的候选数、修订数、实际规格、工具耗时和已知缺陷；模型/队列耗时由平台轨迹核对。

**strict_single_pass：** 一次完整源码候选、零质量改稿、零技术修补，源码出错即保留错误并结束，不另写候选。工具执行不等于新候选；它不保证 CC 只有一次 LLM 请求，按实际轨迹统计。

**常规快速模式：** 无可播放视频时，只允许一次针对语法/路径/编码错误的局部技术修复；不因此重新设计。用户追加微调仅改指定内容，复用原素材和未变片段，最多一次局部实现＋一次技术修复；旧问题不反复修。
