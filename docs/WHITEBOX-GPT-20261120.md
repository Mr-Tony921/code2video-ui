本次只修改 `code2video-dev-codex` 和其授权复用的 dev 数据，生产环境未发布。当前 dev 新会话引擎为 **seko-0.1.10-cvw.1**，新白模默认模型已从下线的 DeepSeek SFB 改为 `gpt-6.1-sol/azure_L/sfa`。本报告是工程验收记录，不等同业务方确认视觉质量。

## 固定流程

- Responses 接口；上下文配置 262144，输出上限 32768。上下文是渠道配置值，不是最大能力探测结论。首稿与审查 low，源码修正 high。
- 业务 JSON 保留完整片段、镜头、参考图；明确完整的文本分段可确定性整理，其余自然语言只做一次必要 intake。没有额外扩写模型或隐藏整案重试。
- 首轮初稿最多2次源码修正；追问基于最后交付源码，一次编辑最多1次修正。失败轮不覆盖可用基线，旧会话固定模型/引擎快照。
- 每个候选做真实 Three.js 回放、片段时间/镜头结构检查、拼图审查。仅证据不足时保留 uncertain，不通过改场景来制造证明，也不把它计为质量通过。
- 人物按剧情需要加四肢和姿态；简单人形、低动态动作优先。修正只处理明确缺陷，不为所有人补细节。
- 每次调用保留 stage、实际输入图片及原图/发送 SHA、请求参数、完整性判定和传输分段；源码和下载包不含密钥。

## 实测口径

工程时间包含必要 intake、模型、探针和有限审查。扣除上传时间使用客户端实测请求提交时间；视频渲染另计。响应等待仍可能包含上游上传、排队与推理；下载慢也会拉长调用，不能称为纯推理耗时。600秒是软目标，未修改为整案强杀。

## 网页联调发现与修复

0.1.9 的真实网页输入使用普通 `镜头1（0–6秒）`，intake 返回原文片段后，宿主只识别 `【镜头1】` 等旧标记而拒绝；随后 FAILED 的临时 SSE 快照尚无 failure 详情，任务卡读取 null 导致页面异常。

0.1.10 补丁支持普通镜头标记、逐字保留片段，识别括号内明确时间区间并拒绝间隙/重叠。前端 failure 类型和显示允许空值，显示真实的“错误详情暂未返回”，不会崩溃。新增实际 React 组件渲染回归与输入时长回归；未新增模型调用或放宽修正次数。

## 最终验收与边界

20组固定回归通过（含真实浏览器 runner、取消/重启接管、权限、输入解析、源码恢复与有限追问）；另7项参考图/预览交付回归通过，Next构建与类型检查通过，技能格式校验通过，dev发布检查16项通过。一次前端构建因旧 Next 缓存路径失败，清除可再生缓存后成功；构建期间后端任务继续运行。三条实际长案例的最终视频全片解码、ZIP完整性均通过。

五分钟补测达到“扣上传后约10分钟出可回放工程”的速度，但质量仍有实际遮挡、特写目标出框及接触问题。其中57条模型审查项可修复、14条为证据不确定，另有工具/错误条目；条目数不是失败镜头数。独立有限抽样也看到了矿脉特写未对准等缺陷。不能用可渲染或结构通过代替质量通过，也不能据此宣称复杂故事已稳定10分钟达到生产效果。

本次固化的是可在 dev 继续使用和验证的版本；生产发布与复杂故事质量验收仍需后续推进。没有通过降低已知缺陷的判定来伪造成功率。接手前其他实验版本保留在原目录，未混入本次默认发布。
