## 1. 产品定位

这**不是**通用 ChatGPT，也**不是**一次性 Text-to-Video 页面，而是：

> 支持多轮交互、Prompt 增强、人工确认、超长任务执行的 **AI 视频创作 Agent 试用平台**。

两个模式共享会话系统、Prompt 增强、任务管理、视频展示与计算资源：

| 模式 | 值 | 可见性 |
|---|---|---|
| Coding to Video | `coding_to_video` | 全部用户 |
| 3D Blockout（白模预演） | `blockout_3d` | 仅 `can_use_blockout_3d=true` 的用户与管理员 |

### 2.1 顶部导航

| 元素 | 行为 |
|---|---|
| Logo + 产品名 | 回到当前会话 |
| **Beta 测试版** 徽章 | 橙色 pill，始终可见，不可关闭 |
| 模式切换 Segmented Control | 无白模权限时该项**置灰 + Tooltip**「需管理员授予白模预演权限」；**不隐藏**，让用户知道能力存在。切换模式**不改变当前会话**，仅影响「下一次新建会话」的默认模式，切换时提示「新模式将在新建会话时生效」 |
| 用户菜单 | 用户名、角色徽章、白模权限标识、修改密码、退出登录 |
| 管理后台入口 | **仅 `role=admin` 可见** |

### 2.2 左侧区域

| 区块 | 内容 |
|---|---|
| **新建会话** | 主按钮；若当前有运行中 Job → 先弹确认框（见 §6.3） |
| **当前会话** | 单卡片：标题、模式徽章、绑定状态。`DEGRADED` 时显示 ⚠️ 与「后端进程已失联」 |
| **进行中的任务 (n)** | 来自 `GET /api/me/jobs?status=active`；每项显示状态图标、已运行时长、Prompt 摘要；点击跳转或打开任务详情抽屉 |
| **最近结果 (n)** | 最近完成的 Job，缩略图 + 时长；点击直接播放 |

> V1 **不做**完整历史 Session 列表、搜索、收藏、归档（任务 2.1 / 8.5）。
> 「进行中的任务 / 最近结果」是**最小任务恢复入口**，保证算完的产物用户一定拿得到。

### 2.3 主区域消息类型

| 类型 | 渲染 |
|---|---|
| 用户消息 | 右对齐气泡 |
| Agent 文本 | 左对齐气泡，支持 Markdown |
| **Prompt Review Card** | 见 §4 |
| **Job Card** | 见 §5 |
| **视频结果卡片** | HTML5 播放器 + 元信息 + 下载 + 继续修改 |
| 系统提示 | 居中细条（如「后端进程已失联」「权限已变更」） |
| 超范围提示 | 来自后端 `intent=out_of_scope` 的**结构化提示**，前端只渲染不判断（见 §3.2） |

### 2.4 底部输入区

- 多行自适应文本框，`Enter` 发送 / `Shift+Enter` 换行
- 发送按钮：生成中禁用并显示原因（见 §6.4）
- **创作意图快捷操作**：`🎬 新视频` / `✂️ 修改当前视频`（无可修改视频时置灰）/ `💬 讨论`
  —— 这些仅为输入模板提示，**真实意图判定始终在后端**
- 输入框下方常驻测试站点提示
- 草稿自动存 localStorage（任务 11.11「输入框未发送草稿」），切换会话不丢失

### 2.5 明确不出现的 UI（V1，任务 3.1 / 测试 O）

```text
❌ 上传按钮        ❌ 拖拽上传区    ❌ 文件预览
❌ 上传进度条      ❌ 外部视频导入  ❌ 任何附件入口（含置灰的）
```

> 任务 3.1 原文：「不要保留无法正常使用的附件入口。」
> 首次使用说明中注明：**后续版本计划支持图片、视频、音频作为 Reference**。

### 3.2 超范围输入（任务 2.2 关键约束）

**前端不做关键词判断。** 用户输入一律提交后端，由后端返回结构化意图：

```jsonc
{ "intent": "out_of_scope",
  "notice": { "code": "OUT_OF_SCOPE",
              "title": "该请求超出本平台范围",
              "message": "本站仅支持 AI 视频生成、视频修改及相关创作讨论。",
              "suggestions": ["描述你想生成的视频画面", "对当前视频提出修改意见"] } }
```

前端渲染为提示卡片 + 建议 chips。这样可避免「看起来像通用 ChatGPT」，同时保证判定口径统一、可随后端策略调整。

## 4. Prompt 增强与确认流程

### 4.1 状态对应的 UI

| Workflow 状态 | 卡片形态 |
|---|---|
| `ENHANCING` | 骨架屏 + 「正在增强提示词…」+ 旋转图标 |
| `AWAITING_APPROVAL` | 完整 Review Card（下图） |
| `REVISING` | 当前版本置灰 + 「正在生成新版本…」 |
| `ENHANCE_FAILED` | 红色边框 + 真实失败原因 + [重试] [放弃] |
| `APPROVED` / `JOB_CREATED` | 折叠为摘要条「已确认（第 2 版）」，可展开 |
| `ABANDONED` | 折叠灰条「已放弃」 |

```text

│ 状态：待确认                              [查看版本历史 ▾] │

│ 赛博朋克风格城市夜景，雨后湿滑街道反射霓虹灯光，镜头从       │
│ 地面缓慢上摇至高楼天际线，时长 10 秒，24fps，电影感调色…    │
├────────────────────────────────────────────────────────────┤
│ 💬 你的修改意见（可选）                                     │
│ ┌────────────────────────────────────────────────────────┐ │
│ │ 希望镜头运动再慢一些，增加雨滴特写                      │ │
│ └────────────────────────────────────────────────────────┘ │
│                                                            │
│      [ ✓ 确认生成 ]   [ ✎ 提交修改意见 ]   [ ✕ 放弃 ]      │

│  ⓘ 确认后将创建生成任务，预计耗时 1~2 小时                  │
└────────────────────────────────────────────────────────────┘
```

### 4.2 交互守卫

| 风险（任务 6） | UI 处理 |
|---|---|
| **双击确认** | 点击即禁用按钮 + 本地 in-flight 标记；服务端 `workflow_id` UNIQUE + `idempotency_key` 兜底，第二次返回同一 `job_id`，UI 无感 |
| **过期 Prompt 版本** | 请求带 `revision_id`；收到 `409 REVISION_STALE` → 不报错，静默刷新到最新版本并提示「提示词已更新到第 3 版，请重新确认」 |
| **增强失败** | 显示后端真实错误，提供 [重试]；**不**自动重试 |
| **修改意见重复提交** | 提交后输入框禁用 + `idempotency_key` 去重 |
| **页面刷新** | workflow 状态在服务端，刷新后原样恢复（任务 11.3） |
| **断线重试** | API Adapter 对幂等请求自动重试；非幂等请求带 `idempotency_key` 后才重试 |
| **权限变化** | 确认时服务端重新校验 mode 权限；`403` → 卡片转为「权限已变更，无法提交白模任务」 |
| **后端执行状态未知** | 确认请求超时但可能已创建 → 前端用同一 `idempotency_key` 重试，服务端返回已创建的 `job_id`，**不产生第二个任务**（任务 11.11） |

**绝不自动提交**：只有用户点击「确认生成」才创建 Job（任务 6）。

### 5.2 时间显示规则（任务 7.4）

| 字段 | 来源 | 文案 |
|---|---|---|
| 已排队时间 | `now - queued_at` | 「已等待 2 分 14 秒」 |
| 已生成时间 | `now - started_at` | 「已运行 1 小时 23 分」 |
| 当前阶段耗时 | `now - phase_started_at` | 「本阶段已 18 分」 |
| 状态新鲜度 | `now - last_progress_at` | 「最后状态更新于 18 秒前」 |
| Worker 健康 | `job.worker_health` | 「后端正常执行」/「正在确认后端状态」 |
| 真实进度 | `progress_percent`（可空） | **为空则不显示进度条**，改用不确定动画 |

**倒计时用服务端时间戳计算**，客户端只做 `now - server_ts` 的本地渲染；
客户端时钟偏移由首次响应的 `Date` 头校正。**不使用前端定时器伪造进度**（任务 7.4 原文）。

## 6. 边界交互（任务 11 全覆盖）

### 6.1 用户反复点击生成（11.1）
按钮点击即禁用并显示 spinner；服务端 `(user_id, idempotency_key)` 与 `workflow_id` 双 UNIQUE 兜底。
多标签页同时确认 → 都返回同一 `job_id`，UI 一致。

### 6.2 提交后关闭网页（11.2）
任务卡片常驻提示：**「任务已提交至服务器，关闭网页不会影响生成。稍后重新登录可查看结果。」**
无 `beforeunload` 拦截弹窗（不可靠且打扰）。

### 6.3 新建 Session 时有运行任务（11.5 / 8.6）

```text
┌─────────────── 确认新建会话 ───────────────┐
│ 当前会话有 1 个正在执行的生成任务：          │
│   ⟳ 赛博朋克城市夜景 · 已运行 1 小时 02 分   │
│                                            │
│ ✅ 新建会话不会中断它，任务将继续在后台执行   │
│ ✅ 可随时在左侧「进行中的任务」查看结果       │
│ ⓘ 新会话将使用独立的后端上下文，              │

│                                            │
```

### 6.4 生成过程中继续发消息（11.4）

取决于后端能力（阻塞项 B-1）。默认采取**保守策略**：

```text
输入框禁用 + 提示:
  「当前会话有生成任务正在执行，完成后可继续对话。
    你可以同时打开新会话进行其他创作。」
```

若后端确认支持会话期并发对话，则放开输入并在消息前加「排队中」标识。
**绝不**因用户连发消息而破坏正在运行的 Agent 上下文（任务 11.4 原文）。

### 6.5 多次点击停止（11.6）
首次点击后按钮转为「正在停止…」并禁用；重复请求幂等，不产生错误态。

### 6.6 完成瞬间点击停止（11.7）
服务端裁决（完成优先）。UI 收到 `409 JOB_ALREADY_TERMINAL{status:COMPLETED}` →
提示「任务已在取消生效前完成」并直接展示视频，**不显示错误**。

### 6.7 登录失效（11.8）
任何 API 返回 401 → 弹出轻量登录框（**不跳走、不清空页面**）。
文案：「登录已过期，请重新登录。你的生成任务仍在后台运行，不受影响。」
登录成功后自动重放原请求。

### 6.8 权限变化（11.9）
白模权限被撤销 → 下次交互时模式切换项置灰，当前白模会话转只读，
系统提示条「白模预演权限已被撤销，已运行的任务将继续完成，产物仍可访问」。

### 6.9 后端长时间无进度（11.10）
见 §5.1「健康但停滞」。四种情形文案区分：

| 情形 | 文案 |
|---|---|
| 正常运行无阶段更新 | 「后端仍在正常执行，当前阶段暂无新增进度」 |
| Worker 心跳异常 | 「正在确认后端机器状态…」 |
| Job 心跳异常 | 「正在确认任务执行状态…」 |
| Scheduler 对账中 | 「系统正在与后端核对任务状态」 |
| 后端确定失败 | 「生成失败：<真实原因>」 |

绝不出现永不变化的「生成中」，也绝不误报失败。

### 6.10 其他边界（11.11）

| 场景 | UI 行为 |
|---|---|
| 网络瞬断 | 顶部黄条「网络连接中断，正在重连…」；恢复后拉快照 + 续订事件 |
| 多标签页 | `BroadcastChannel` 即时同步 + 各自 SSE 兜底 |
| 同 Session 并发提交 | 服务端串行化；UI 显示「有请求正在处理」 |
| 超长 Prompt | 输入框显示字数；超限前端提示 + 服务端 `413` 兜底 |
| 未发送草稿 | 自动存 localStorage，按会话隔离 |
| SSE 断线 | 静默降级为轮询，顶部细条提示「实时更新暂不可用，正在定期刷新」 |
| 事件乱序/重复 | 按 `seq` 去重排序，用户无感 |
| 提交成功但响应丢失 | 同 `idempotency_key` 重试 → 返回已创建 Job |
| 产物已写但完成事件丢失 | 轮询/对账补判 `COMPLETED`，UI 自动出现播放器 |
| 文件写一半进程退出 | Asset 非 `READY` → 不展示播放器，显示「产物不完整」 |
| Worker/Scheduler 重启 | 对用户不可见（任务不中断） |
| 运行中退出登录 | 提示「你有 1 个任务仍在运行，退出不会中断，重新登录后可查看」 |
| 管理员禁用账号 | 下次请求 401/403 → 「账号已被禁用，请联系管理员」 |
| 取消送达但进程失联 | 「已请求停止，但后端进程失联，无法确认计算是否终止」（不谎称成功） |

## 7. 视频播放与下载

### 7.1 播放器（任务 13.2）

HTML5 `<video>` + 自定义控制条：播放/暂停、进度跳转、音量、全屏、倍速、横竖屏自适应。

| 状态 | 展示 |
|---|---|
| Asset 未就绪 | 骨架屏 +「结果准备中…」 |
| 加载失败 | 「视频加载失败」+ [重试] + [直接下载] |
| 浏览器不支持编码 | 「当前浏览器不支持该视频格式，请下载后观看」 |

播放源为 `GET /api/assets/{id}/playback`（短期签名或会话校验的流式地址），
**绝不暴露共享存储路径**（任务 13.3）。

### 7.2 下载

`GET /api/assets/{id}/download` → `Content-Disposition: attachment`，支持 HTTP Range 断点续传。
大文件以流式转发，不整体读入 Web 进程内存。

### 7.3 继续修改（任务 3.2）

点击「继续修改这个视频」→ 输入框预填「修改这个视频：」+ 隐含 `base_asset_id=A`。
后端基于 A 生成 B，**B 与 A 均独立保存**（`derived_from_asset_id` 关联），原文件不被覆盖。
结果区以版本链展示：`v1 → v2 → v3`，各版本均可播放下载。

## 8. 管理后台（`role=admin`）

### 8.1 邀请码管理

```text
┌─── 邀请码 ──────────────────────────────────────────────────┐
│ [ + 生成邀请码 ]                                             │
│ ┌──────────┬──────┬───────┬────────────┬──────┬──────────┐ │
│ │ 前缀      │ 用量 │ 白模  │ 有效期至    │ 状态 │ 操作      │ │
│ ├──────────┼──────┼───────┼────────────┼──────┼──────────┤ │
│ │ SNV-3F2A │ 0/1  │  ✓    │ 2026-10-30 │ 有效 │ [撤销]    │ │
│ │ SNV-9B1C │ 1/1  │  ✗    │ 2026-10-28 │ 用尽 │ —        │ │
│ └──────────┴──────┴───────┴────────────┴──────┴──────────┘ │
└──────────────────────────────────────────────────────────────┘
```

生成弹窗：使用次数（默认 1）、有效期（默认 7 天）、是否授予白模权限。
**创建后一次性全屏展示完整邀请码 + 复制按钮，并明示「关闭后无法再次查看」**（仅存哈希）。

### 8.2 用户管理

列表：用户名、角色、白模权限开关、状态、注册时间、最近活动、运行中任务数。
操作：启用/禁用、授予/撤销白模权限、重置密码（生成一次性临时密码）、查看其任务。

撤销白模权限时二次确认，明示：

```text
撤销后该用户将无法创建新的白模会话或提交新的白模任务。
⚠️ 已在运行的任务将继续执行至完成，如需终止请在任务列表中单独操作。
用户仍可访问自己已完成的合法产物。
```

这直接对应任务 4.3「权限管理与任务取消不能混为一谈」。

### 8.3 任务与容量总览

`GET /api/system/capacity` + 全局任务列表：各 Worker/Process 健康状态、并发占用、运行中任务、管理员终止入口（二次确认 + 审计留痕）。
